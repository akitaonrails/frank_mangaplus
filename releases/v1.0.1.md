# FRANK MANGA+ v1.0.1

Reading-flow fix: aggressive image preloading.

## Sliding eager-load window

- Previously only the first 3 pages of a chapter were eager-loaded;
  everything else relied on browser-native lazy loading, which starts a
  fetch only when the image is nearly on screen. With full-viewport page
  frames and flip/jump navigation, the reader routinely landed on an empty
  placeholder and made the user wait (or wiggle back and forth) for the
  page to appear.
- Images now use a sliding eager window around the reading position:
  10 pages ahead and 3 behind are always fetching, following the reader as
  they advance. Far-away pages stay lazy so opening a chapter doesn't pull
  an entire title's worth of `super_high` images at once.
- The window pairs with the existing next-chapter prefetch (which fires
  8 pages from the end of the loaded scroll), so freshly appended chapter
  pages start downloading as soon as they enter the window.

## Tests + verification

- New unit coverage for the window logic: edges ahead/behind, lazy outside
  the window, and full eager coverage of a freshly opened chapter's first
  pages (95 vitest tests total).
- `./verify.sh`: all green — Rust tests/clippy, Vitest, `svelte-check`,
  production build, and Vite dev CSS probe.
