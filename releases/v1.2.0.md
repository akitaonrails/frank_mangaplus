# FRANK MANGA+ v1.2.0

Spread-aware double-page layout.

## Two layouts instead of three, paired as printed (#10, closes #9)

The reader's double-page mode now reads the API's spread markers instead of
pairing pages blindly by position.

Previously there were three layouts — `single`, `double` (pairs from page 1),
and `double-cover` (cover solo, then pairs) — and a two-page spread only
stayed whole when its halves happened to land on the parity of the layout you
picked. You had to cycle layouts with `D` per title until spreads lined up,
and no single layout worked for every title.

`manga_viewer_v3` is requested with `split=yes`, which delivers each spread as
a RIGHT half followed by its LEFT half (`MangaPage.type`). The reader now uses
those markers:

- **single** — unchanged.
- **double** — facing pages, paired the way each chapter was printed. The
  chapter's first spread fixes where its pairs start: cover binds solo, or
  pairs start on page 1 when the cover itself is a spread. A split spread
  always shares one frame; if a later spread would fall off the chapter's
  parity, the page before it renders solo rather than cutting the spread. The
  decision resets at every chapter boundary.

`D` now toggles `single ↔ double`. A saved `double-cover` preference (global
or per-title) is read as `double`, so no setting is lost.

Known limitation (documented in `reader/docs/spread-pairing-audit.md`): a few
titles — One Piece ch1–3 among them — deliver real spreads *unmarked* as
consecutive single pages. Detection can't fire there, so those chapters use
the cover-solo default, which matches print for them by parity. An
image-based fallback is noted for future work.

## Tests + verification

- 11 new `buildPageGroups` unit cases built from live chapter layouts (Hey!
  Devil Girl! #001, Home at the Horizon #001): cover-solo, cover-as-spread,
  even/odd first-spread offsets, off-parity spreads, orphan halves, and
  chapter-boundary safety. 166 vitest tests total.
- `./verify.sh` on merged main: all green — Rust tests/clippy, Vitest,
  `svelte-check`, production build, and Vite dev CSS probe. CI green on the
  merge commit across ubuntu/macos/windows.
