# FRANK MANGA+ v1.3.2

This patch release restores image rendering in the Windows build.

## Windows image rendering (#21)

Windows WebView2 represents Tauri custom protocols as an HTTP-shaped local
URL. The reader previously emitted the native `mpimg://` form directly, so
cover and chapter image requests never reached the Rust image proxy on
Windows.

Image sources now use Tauri's platform-aware URL conversion. The Rust handler
decodes both the Windows and native forms, preserves signed MANGA Plus CDN
queries, and accepts only HTTPS targets on the MANGA Plus CDN boundary.

## Dependency and security maintenance

- Patched WebPKI certificate and root-store crates resolve the three current
  RustSec vulnerabilities without changing the CDN-fingerprint-sensitive
  `wreq` and `wreq-util` pins.
- Compatible Tauri CLI, Vite, Vitest, and Svelte-check patch updates are
  included. A patched `cookie` override clears the advisory inherited through
  the current SvelteKit 2 release line without adopting breaking framework
  major versions.
- `cargo audit` and `bun audit` report no known vulnerabilities. The remaining
  RustSec notices are upstream maintenance/unsoundness warnings in Tauri's
  Linux GTK dependency graph.

## Tests and verification

- New regression tests cover the Windows and native custom-protocol URL forms,
  signed-query preservation, retry cache busting, non-Tauri rendering, and
  rejection of untrusted proxy targets.
- All 179 Vitest tests and 70 desktop Rust tests pass.
- A live device-registration/profile smoke test passed after the trust-store
  updates; the exact CDN TLS-fingerprint pins remain unchanged.
- `./verify.sh` is green: Rust tests and Clippy, Vitest, `svelte-check`, the
  production frontend build, and Vite development CSS probes.
