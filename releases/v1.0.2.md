# FRANK MANGA+ v1.0.2

Stability release: expired-URL recovery and image-cache garbage collection.

## Signed-URL expiry recovery (broken pages after sleep / long sessions)

- Page image URLs are signed with an `expires=` timestamp valid for roughly
  1-2 hours, and premium fetches also depend on the `plus_vw_token` cookie
  minted by the same `manga_viewer_v3` call. After a long idle or a
  sleep/wake cycle both go stale: re-requested pages hit the CDN with a dead
  signature, and the Reload button re-requested that same dead URL forever —
  the "broken placeholder at best" loop.
- The reader now detects expired signatures (with a 5-minute safety margin)
  and re-fetches the owning chapter to mint fresh URLs — refreshing the
  cookie as a side effect — then swaps them into the page list in place.
  Retry bookkeeping for replaced URLs is dropped so it can't accumulate.
- Recovery triggers from four directions: image error on an expired URL,
  the manual Reload button / R key, window visibilitychange (wake/refocus),
  and a minutely background sweep — which also covers machines that sleep
  with the window visible and slow reads that outlive the signature.

## Image-cache garbage collection

- The on-disk image cache was never evicted and grew unboundedly (observed:
  4.8 GB across 10,011 files). A startup GC now prunes the image subtree to
  a byte budget — oldest-mtime files first, so recently read chapters stay
  warm. Default budget 2048 MB; `MANGAPLUS_IMAGE_CACHE_MAX_MB` overrides.
  The catalog SWR cache is never touched.

## Tests + verification

- 5 new Rust tests for the cache GC (oldest-first order, budget edges,
  empty-directory cleanup, missing dir, zero budget) and 5 new vitest cases
  for expiry parsing and margin behavior — 100 vitest + 29 Rust tests total.
- `./verify.sh`: all green — Rust tests/clippy, Vitest, `svelte-check`,
  production build, and Vite dev CSS probe.
