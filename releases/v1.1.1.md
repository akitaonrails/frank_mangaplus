# FRANK MANGA+ v1.1.1

Patch release: the reader's broken-image recovery actually recovers now, and a suspended laptop can no longer wedge image loading for good.

## Reader image recovery

- The broken-image retry — both the automatic retry ladder and the manual "↻ Reload page" button — used to change only the URL **fragment** (`#attempt=N`). Per the HTML spec, an `<img>` whose src changes only in the fragment is never re-fetched, so every retry was a no-op; leaving the chapter and re-entering was the only recovery. Retries now bust the load with a `?mpretry=N` **query** parameter (stripped by the `mpimg://` handler before the CDN sees it, so the signed URL is untouched), and the reader recreates the `<img>` element on each attempt — WebKit remembers a failed load on the element itself.
- The HTTP client had **no timeouts at all**. After the machine sleeps (laptop lid closed), a dead pooled connection would hang a fetch until the OS TCP timeout (~15 min) — and a hung fetch holds an image-fetch slot the whole time, so enough of them parked every slot and nothing would ever load again until restart. Pool-idle (30s), connect (15s), and request (60s) ceilings are now in place.
- The reload overlay's page number now matches the progress bar (chapter-relative) instead of counting across every chapter loaded in the session, so the two no longer disagree after a chapter boundary.

These complete the fix class reported in #2 alongside the expired-URL re-signing shipped in v1.0.2.
